# Explicit terrain-cost prototype policy (ZOD-012)

Date: 2026-10-22. Managed starting commit: `2aa8f0c`. This integrates the existing [bounded terrain propagation proof](movement-inputs.md); it is not a new original-game rule translation. Historical source provenance remains pinned in that note and the [adjacent-step investigation](adjacent-step-geometry.md). New integration expectations are synthetic, not executing-reference or original observations.

`BattleSimulator.Apply(state, command, movementPolicy)` explicitly selects `FlatGridPrototype` or `TerrainCostPrototype`. The existing two-argument overload delegates to `FlatGridPrototype` to preserve callers. Invalid policy values fail with an argument error. Existing command rejection order and immutable state/event handling are preserved for valid policies.

The flat policy still uses the FFT facade over Zodiac's bounds-only calculation. The terrain-cost policy remains FFT-owned and calls `TerrainAwareMovementRange` with the effective profile and explicit traversal blockers. No FFT terrain flags, cost tables, special movement semantics or compatibility branches enter Zodiac. This task does not generalize weighted search or change the one-way project dependency.

The terrain policy charges each entered tile's resolved surface cost, respects Move, rejects blocked tiles/surfaces, and excludes Cannot Stop and Untargetable endpoints while allowing propagation through those two flags. All other units block traversal and destinations, irrespective of allegiance or state. This conservative choice is an explicitly synthetic prototype rule: original allies, enemies, mounts and standing-height paths are not implemented. Occupants on other layers do not block the selected same-layer positions. The mover's own occupied origin is not added as a blocker. Occupied-destination rejection still precedes range calculation. The three-argument standalone range helper keeps its original occupancy-free behavior; the new overload takes explicit blockers.

Missing terrain costs still raise `InvalidOperationException` naming the surface rather than returning a misleading movement rejection or inventing a default cost. No state is changed before the calculation returns. Checked cost addition remains unchanged. Cost maps are supplied as effective values; Jump, height, slope, water, ceilings, special movement modes/traits, weather resolution and interlayer transitions are not interpreted by this policy. Supplying those fields does not enable their mechanics. This policy is deliberately named a prototype, not a PS1 compatibility profile.

Fixture v1 gains support for the additional policy ID `fft:movement/terrain-cost-prototype` with the same explicit state and event schema; `fft:movement/flat-grid-prototype` remains supported. This is a policy capability extension, not a serialized shape change. The new accepted/rejected synthetic fixtures use a cost-two tile with Move two/one respectively. Historical source descriptions remain unexecuted, and flat fixtures continue to exercise the preserved flat policy explicitly.

Coverage includes entry-cost thresholds, available movement, destination and intermediate tile flags, blocked surfaces, occupied intermediate/destination positions, an affordable detour around an occupant, missing-cost diagnostics, invalid policy, state immutability and exactly one accepted event. Existing standalone tests cover cheaper alternative routes. After parallel definitions integration, locked restore passed, Release build passed with zero warnings/errors, and all 227 solution tests passed (91 Core, 38 Content, 22 engine, 76 asset tool/CLI). A separate agent review found no actionable integration issues. No runtime BIN, C dependency, assets, renderer, network or emulator is introduced. Linux CI has not been run locally.
